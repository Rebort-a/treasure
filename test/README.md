# 测试范围

测试主要保护运行正确性，而不是固定界面的具体设计。

## 保留的测试

- 游戏规则、胜负判定、合法操作、AI 决策和状态序列化。
- 联机认证、密码校验、消息路由、匹配顺序、同步、重发去重、断线重连、发布者接管和重开。
- 持久化、旧数据兼容、非法输入和异常处理。
- 关键用户流程：加入房间、进入游戏、操作棋盘、重开、返回和取消。
- 页面及管理器生命周期：资源释放、旧局计时器失效、延迟消息不会污染新局。
- 模块与分层依赖边界、纯 Dart 内核边界，以及测试工具自身的关键行为。

## 不应固定的细节

- 文案原文、标点、图标种类或位置、卡片排版和控件排列顺序。
- 颜色、边框、间距、固定宽高和像素坐标。
- 粒子、撒花、入场轨迹、动画中间帧、精确动画时长和路由过渡样式。
- 为验证外观而检查内部控件树、具体组件类型或源文件目录形状。

## 新增或修改测试时

1. 先说明失败会导致什么运行错误或关键功能失效；仅外观不同不应使测试失败。
2. 使用操作后的状态、消息结果、导航结果和是否抛错作为断言依据。
3. 控件定位优先使用已有的操作键或语义；按文案定位时使用 `S`，避免写死翻译原文。
4. 避免按输入框索引定位，不要求某一控件树结构或精确的元素数量。
5. 动画测试只关心完成后是否可操作、是否能重开、是否释放资源，不关心具体表现形式。
6. 合并重复覆盖；不锁死插件所在文件、资源编码参数或目录文件集合，也不以降低覆盖率门槛代替行为验证。

## 验证

```bash
flutter analyze lib
flutter test --coverage
dart run scripts/coverage_report.dart --check --json=coverage/summary.json
```
